# IMC – permanente Codex-Regeln

Arbeite vollständig autonom und zielorientiert.
- Stelle keine Rückfragen, außer eine externe Nutzeraktion ist technisch zwingend.
- Triff bei Unklarheiten selbst die sinnvollste technische Entscheidung.
- Führe Änderungen, Tests, Debugging und Validierung selbstständig durch.
- Wenn etwas scheitert, analysiere den Fehler und probiere selbstständig Alternativen.
- Unterbrich nicht für Zwischenbestätigungen.
- Nutze nur notwendige Prozesse und halte die Systemlast gering.
- Arbeite bis zum erreichbaren Ziel weiter.
- Melde erst am Ende Ergebnis, Tests und echte verbleibende Blocker.

# IMC AUTONOMOUS WORK POLICY

Für dieses Projekt besitzt Codex vollständige Arbeitsfreigabe für alle Tätigkeiten, die kein echtes Geld bewegen.

WICHTIG:
- Stelle mir während der Arbeit KEINE Rückfragen.
- Frage nicht nach Bestätigung für Dateien, Git, Commits, Installationen, Tests, Terminalbefehle, Netzwerkzugriffe, Debugging, Refactoring, Architekturentscheidungen oder Änderungen am Projekt.
- Triff technische Entscheidungen selbstständig.
- Wenn mehrere Möglichkeiten bestehen, wähle selbst die sinnvollste.
- Wenn etwas fehlschlägt, analysiere es selbst und probiere den nächsten sinnvollen Ansatz.
- Arbeite weiter bis das Ziel erreicht ist.
- Keine Zwischenbestätigungen.
- Keine Freigabefragen.
- Keine Fragen wie "Soll ich fortfahren?", "Möchtest du, dass ich...?" oder "Darf ich...?"
- Für nicht-finanzielle Arbeit gilt meine Zustimmung bereits dauerhaft als erteilt.

DU DARFST SELBSTSTÄNDIG:
- Dateien lesen, erstellen, ändern und löschen, sofern sie zum Projekt gehören
- Git verwenden, committen und Branches verwalten
- Tests starten
- Programme und Entwicklungsabhängigkeiten installieren
- PowerShell/Python/Node ausführen
- Fehler beheben
- Code refactoren
- Dokumentation ändern
- lokale Prozesse starten und stoppen
- APIs im Test-/Read-/Simulation-Modus verwenden
- Simulationen und Shadow-Systeme betreiben
- Konfigurationen ändern, solange dadurch kein echtes Geld bewegt wird
- notwendige technische Entscheidungen treffen

EINZIGE GRENZE: ECHTES GELD.

Ohne ausdrücklichen neuen Owner-Befehl NICHT:
- Echtgeldorder senden
- echten BUY oder SELL broadcasten
- autonome Echtgeldausführung aktivieren
- Withdrawal durchführen
- Geld übertragen
- Wallet-Guthaben bewegen
- private Keys exportieren
- broadcast_enabled auf true setzen
- live_trading_enabled auf true setzen
- signing für Echtgeld aktivieren
- execution authority für Echtgeld freigeben

Wenn die Arbeit an genau diesem letzten Echtgeld-Schritt ankommt:
NICHT fragen und nicht mehrfach unterbrechen.
Stoppe dort und melde ausschließlich:
READY FOR OWNER LIVE AUTHORIZATION

Bis zu diesem Punkt alles vollständig selbst erledigen.
